# 板块势能 · 五阶段模型

> 一套只观察**资金行为**的板块阶段判断框架。
>
> **主线（从头到尾只有这一条）**：
> 脚印出现 → 脚印变多 → 脚印方向一致 → 脚印密集 → 猎人太多 → 推进效率下降 → 猎物消失。

**它不是技术指标模型，而是资金行为模型。** 这句话决定了后面所有取舍。

**核心哲学**：只观察**资金行为在价格和成交量上的结果**。
所以不需要分钟数据、Level-2、龙虎榜、主力资金、资金流、新闻 ——
价格 + 成交量 + 成交额 + 涨跌幅，就够第一版。

---

## 一、模型只回答两个问题

| # | 问题 | 输出 | 在哪一层回答 |
| :-: | --- | --- | :-: |
| 1 | 这个板块**现在**在哪个阶段？ | ① ② ③ ④ ⑤ | **判断·Layer 1 · Regime** |
| 2 | 它**正在往哪里**移动？ | ↑ 升温 / → 维持 / ↓ 降温 | **判断·Layer 2 · Momentum** |

> **位置告诉你该不该看，方向告诉你该不该动手。**
> 真正值得交易的往往不是「成型」，而是「**成型 + 正向移动**」。

---

## 二、指标纪律（最重要的一条规则）

每个指标**必须回答下面五个问题之一**，答不上来就删掉：

```
钱来了没有？  →  钱有没有留下？  →  有没有更多股票参与？ →  钱产生了多少价格推进？  →  是不是已经太拥挤？
```

> ⚠️ **最容易掉进的陷阱：指标大杂烩。**
> 成交额 + 涨幅 + 涨停 + 换手 + RSI + MACD + KDJ + 布林 + ATR + 资金流 + 主力 + 北向 + 融资……
> 一旦这样堆，五阶段模型就被技术指标淹没了。
>
> **本书所有指标都严格限制在上面五个问题之内，板块层控制在 15 个左右。**

## 三、数据架构（整个系统最关键的一层）

### 3.1 一句话架构

> ### 东方财富只做「板块字典」，Tushare 提供「全市场行情」，所有指标在本地算。

| 数据 | 谁提供 | 作用 |
| --- | --- | --- |
| 个股 OHLCV | **Tushare** | 核心行情 |
| 个股涨跌幅 | **Tushare** | Breadth / RS |
| 个股成交额 | **Tushare** | Flow |
| 板块分类 | 东方财富 | 板块定义 |
| 板块成分股 | 东方财富 | **股票 → 板块** 映射 |
| 所有指标 | **本地计算** | Flow / Breadth / Efficiency / Crowding / Stage |

> **东方财富不是你的行情数据库，它只是你的「板块字典」。**

**东财反爬的根源是「定位」，不是「频率」：**

| ❌ 危险定位 | ✅ 安全定位 |
| --- | --- |
| 东财 → 每天拉 5000 只股票行情 → 每天算所有东西 | 东财 → 「哪些股票属于这个板块？」→ 存本地 → **用完就不再访问** |

右边这一侧，接口变化、结构变化、访问限制都影响不到你。

### 3.2 关键一步：按「交易日」拉全市场，**不要**按板块拉股票

❌ 这样会把自己做成一个很别扭的爬虫（500 个板块 = 500 轮）：

```
板块A → 拉A的50只  → 算 Breadth
板块B → 拉B的80只  → 算 Breadth
板块C → 拉C的120只 → 算 Breadth
```

✅ 反过来做：

```
每天收盘
   ↓
Tushare daily(trade_date)  ← 1 次请求，拿到全市场约 5000 只
   ↓
存本地
   ↓
板块成分映射（本地）
   ↓
板块A Breadth · 板块B Breadth · 板块C Breadth …   ← 全是本地计算，零网络请求
```

> **行情只拉一次，板块计算全部在本地完成。**
>
> **Tushare 120 积分刚好够**：daily 每分钟 50 次 / 每天 8000 次 / 单次最多 6000 条，
> 且官方明确建议 —— **循环日期提取全市场，不要循环 ts_code**。
> 所以每天是 **约 1 次请求**，不是 5000 次。这跟"反爬"完全不是一个量级。


### 3.3 原始数据 vs 派生数据：随时重建，不要绑死

| 类型 | 存什么 |
| --- | --- |
| **原始数据** | `stock_daily`（个股日线，全市场）· `board_daily`（板块日线）<br>`stock_list`（个股字典：代码→名字）· `board_list`（板块字典）· `concept_member`（板块成员，**快照**） |
| 派生数据 | 个股因子、板块 Flow / Breadth / Efficiency / Crowding、Stage |

> **不要把「板块 Breadth 历史」当原始数据存。**
> 存「个股历史 + 板块成员关系」，然后**随时重建** Breadth。

| 场景 | 结果 |
| --- | --- |
| 新板块（今天才发现"脑机接口"） | 加入成员表即可 —— **历史个股数据已经在** → 立刻算出过去 20/60 日 Breadth |
| 想改口径（MA20 → MA30） | **重算即可**，不用重新采集 |
| 换数据源（东财 → 同花顺） | 只需重建成员表，**后面的 Flow→Breadth→…→Stage 完全不用改** |

#### 成员表为什么用「快照」而不是「历史」

`concept_member(concept, code)` 只有「**现在这个板块有哪些股票**」，没有 start/end 日期：

```
concept_member
  BK1201  300308
  BK1201  000636
  ...
```

理由很直接：**这个系统的用途是「看当下的势能」，不是做跨年回测。**

| | 快照（现在的做法） | 历史（start/end 日期） |
| :-: | --- | --- |
| 看当下势能 | ✅ 完全够 | ✅ |
| 表的大小 | 500 板块 × 平均 100 只 ≈ **5 万行** | 每次调仓都新增一批，几年后几百万行 |
| 维护成本 | 同步一次 = 整块替换 | 要算「哪天进、哪天出」，还得和行情对齐 |
| 跨年回测 | ⚠️ 有幸存者偏差 | ✅ 没有 |

**幸存者偏差有多大，说清楚：**

历史行情是**全量**的（`stock_daily` 存的是每天全市场 5500 只，一只不缺），
所以偏差**只来自「成员名单」这一个维度**：

| 情况 | 影响 |
| :-: | --- |
| 算**整个板块**过去的 Breadth | 用今天的成员去算，等于「按今天的名单回看历史」<br>→ 退市/被剔除的股票不在名单里 → 略微高估 |
| 看**当下**的势能（本系统的用途） | ✅ **没有影响** —— 今天的名单就是今天的名单 |
| 新加入板块的股票 | 它过去 20 天的行情**本来就在库里** → 照样能算 |

> 所以这是一个**明确知道、明确接受**的取舍，不是疏漏：
> 用「几万行的快照」换「几百万行的关系表」，代价是**跨年回测时有个小的乐观偏差**。
>
> 真要回测跨年策略时再补历史成员表 —— 那时**行情数据一行都不用重采**，
> 只要补一张关系表，所有指标重算即可。这正是第 10.2 节说的「历史靠重建」。

### 3.4 数据分三层

| 层 | 表 | 说明 |
| --- | --- | --- |
| **A · Raw** | `stock_daily` · `board_daily` · `stock_list` · `board_list` · `concept_member` | 原始数据，**只采不算** |
| **B · Feature** | `stock_features_daily` · `board_features_daily` | 算出来的因子 |
| **C · Signal** | `board_stage_daily` · `stock_score_daily` · `etf_score_daily` | 最终信号 |

> 这一层分清楚，**模型和数据源就永远不会被绑死**。
>
> 单位约定：**A 层一律存原始单位**（金额 = 元、成交量 = 股），方便程序直接算；
> 换算成「亿 / 万」只发生在**展示**那一步。
>
> 名字（个股 / 板块）**单独放字典表**，不塞进日报：名字很少变，行情天天变；
> 混在一起的话，每天几千行都要重复存一遍同样的名字，改个名字还得改全部历史。

### 3.5 一个必须提前知道的坑：复权

120 积分暂时没有复权权限（`pro_bar`）。除权除息会让**价格绝对值类**指标失真。

| 指标类型 | 有问题吗 | 怎么做 |
| --- | :-: | --- |
| **收益率类**（5D/20D/60D 收益、RS） | ✅ | 用 `∏(1 + pct_chg) − 1` 算累计收益，**不要**用 `close[t] / close[t−20] − 1` |
| 广度类（上涨占比、强势股占比、5日强势、跑赢板块） | ✅ | 直接用 `pct_chg` |
| 成交额异常 | ✅ | `amount ÷ MA20(amount)` |
| **价格绝对值类**（`close > MA20`、`close ≥ 20日最高`） | ⚠️ | 第一版先这么做，**等拿到复权数据后再优化** |

> **不要因为复权问题卡住整个系统** —— 上面三类已经能撑起绝大部分指标。

### 3.6 现在有什么 / 还差什么

| | 状态 |
| --- | --- |
| ✅ **已实现** | **全市场个股日线**（`stock_daily`）· **板块日线**（`board_daily`）· 个股字典（`stock_list`）· 板块字典（`board_list`）· 板块成分股（`concept_member`，快照式）· 自选（`local.sqlite`）<br>—— 全部落在 `data/raw/raw.sqlite` 一张库里，**jsonl 已彻底退役** |
| 🔜 **下一步** | ① 本地算个股状态向量 → 聚合出板块 **Breadth** ② Flow / Efficiency / Crowding ③ Stage 判断 |

> **采集两条铁律**
> 1. **以交易日为准** —— 落盘的每一天由行情自带的交易日决定，不做"今天是哪天"的判断，
>    所以周末和法定节假日都不会算错。
> 2. **历史靠重建，不靠数据商** —— 不要指望"数据商过去有没有帮我保存过这个板块的涨跌家数"。

## 四、板块层：四个因子（约 15 个指标）

### 4.1 Flow · 资金参与度 —— 钱来了多少

| 指标 | 公式 | 回答什么 |
| --- | --- | --- |
| **Flow Ratio**（核心） | 今日成交额 ÷ MA20 成交额 | 钱有没有进来 |
| **成交额趋势** | MA5 成交额 ÷ MA20 成交额 | 资金进入**是否连续** |
| 成交额分位 | 成交额在近 60 日中的百分位 | 是不是历史级别的大量 |
| 成交额横截面排名 | 在全部板块中的成交额排名 | 今天的钱在**哪里** |

> **连续性比爆发更重要**：`0.8→0.9→1.0→1.1→1.3` 比 `0.7→2.0` 更有意义。

### 4.2 Breadth · 扩散度 —— 是一个股票在涨，还是整个板块在涨

> 有了 §3 的架构，Breadth 变成**极其简单的本地聚合**：按板块成员过滤全市场日线即可。

| 指标 | 公式 | 回答什么 |
| --- | --- | --- |
| **上涨占比** | 上涨股票数 ÷ 板块股票总数 | 短期参与 |
| **MA20 上方占比** | 股价 > MA20 的股票数 ÷ 总数 | 中期参与（**比单日涨跌稳定得多**） |
| **20 日新高占比** | 20 日内创过新高的股票数 ÷ 总数 | 强势扩散（**比涨停数量更有价值**） |
| **跑赢板块占比** | 涨幅 > 板块涨幅的股票数 ÷ 总数 | **是否全面上涨，还是只靠龙头拉** |

> **MA20 上方占比**：`30% → 35% → 40% → 48% → 58% → 68%`
> 说明板块内部越来越多股票进入中期强势 —— 完美对应「脚印越来越多」。
>
> **跑赢板块占比**在区分这两种情况时最关键：
>
> | 情况 | 板块 | 内部 | 结论 |
> | --- | :-: | --- | --- |
> | A | +5% | 龙头 +10%、第二名 +8%，其余 48 只平均 +1% | **龙头行情**，Breadth 很差 |
> | B | +5% | 50 只里 40 只 > +3% | **真正的板块行情**，Breadth 很强 |

### 4.3 Efficiency · 推进效率 —— 钱产生了多少价格推进

> ❌ **不要直接用「涨幅 ÷ 成交额倍数」。**
> 不同板块波动特性不同：新能源一天 +2%、小盘科技一天 +6%，**直接相除不可比**。

```
Efficiency = 区间收益率 ÷ (区间平均成交额 ÷ MA20 成交额)
```

| 指标 | 公式 | 回答什么 |
| --- | --- | --- |
| **Efficiency Level** | 5 日收益率 ÷ 5 日成交额放大倍数 | 现在推得动吗 |
| **Efficiency Level（20日）** | 20 日收益率 ÷ 20 日成交额放大倍数 | 中期推得动吗 |
| **Efficiency Trend** | 上面这个值**自己的趋势** | 效率在变好还是变坏 |

> **Level 和 Trend 要分开看。**
>
> | 阶段 | 成交额 | 板块 | 说明 |
> | --- | :-: | :-: | --- |
> | 一 | +80% | +8% | 钱进来，价格跟着走 |
> | 二 | +150% | +4% | **钱越来越多，推进越来越少** → 衰退最早、最准的信号 |

### 4.4 Crowding · 拥挤度 —— 是不是所有人都来了

| 维度 | 指标 | 回答什么 |
| --- | --- | --- |
| 价格 | 5 日涨幅分位 | 短期是不是涨过头 |
| 价格 | 20 日涨幅分位 | 中期是不是涨过头 |
| 资金 | 成交额分位 | 是不是历史级别拥挤 |
| 波动 | 5 日 ÷ 20 日波动率分位 | 风险是不是在放大 |
| 极端 | 涨停占比（_可从全市场数据自己算_） | 情绪是不是极端 |

> 拥挤度不是"涨得多危险"，而是：**所有人都已经进来了，后面还有谁来买？**

### 4.5 辅助指标：回撤恢复能力（Resilience）

> 最贴合「势能」两个字的一个指标：
> **钱进来之后，板块受到一次抛压，还能不能重新被资金接起来？**

```
回撤恢复率 = 回撤后重新收复的幅度 ÷ 之前回撤的幅度
```

| 序列 | 判断 |
| --- | --- |
| `+5% +2% -2% +3% +4%` | **强**：卖压出现了，但资金继续接 |
| `+6% +4% -1% -4% -3%` | **弱**：一有抛压就没人接 |

> 它特别擅长区分 **成型 → 加速**（恢复快）和 **加速 → 衰退**（恢复不了）。

## 五、五个阶段

### 5.1 速查表

| 阶段 | 核心状态 | 四维特征 | 操作意义 |
| :-: | --- | --- | --- |
| **① 沉寂** | 没有资金关注 | Flow 低 · Breadth 低 · Efficiency 无意义 · Crowding 低 | **不关注** |
| **② 发现** | 势开始形成 | Flow ↑ · Breadth ↑ · Efficiency 开始提高 · Crowding 低 | **重点研究** |
| **③ 成型** | 资金行为已被价格确认 | Flow 高 · Breadth 高 · Efficiency 高且稳定 · Crowding 中 | **主要参与区** |
| **④ 加速/狂热** | 资金高度拥挤 | Flow 极高 · Breadth 极高 · Efficiency 高或**开始下降** · Crowding 极高 | **谨慎追高** |
| **⑤ 衰退/分歧** | 推动能力下降 | Flow 高或下降 · Breadth ↓ · Efficiency **明显下降** · Crowding 高→下降 | **减仓/退出** |

### 5.2 三条铁律

| # | 认知 |
| :-: | --- |
| 1 | **沉寂区的特点不是「跌」，而是「没有资金行为」** → 不是预测"什么时候涨"，而是**等脚印** |
| 2 | **狂热 ≠ 马上见顶** → 该说「趋势非常强，但**风险收益比正在恶化**」，而不是「卖」 |
| 3 | **势消失 ≠ 价格跌很多** → 真正的信号是**资金失去了推动价格的能力** |

### 5.3 阶段之间怎么走

| 走向 | 路径 | 识别信号 |
| --- | --- | --- |
| 失败 | 沉寂 → 发现 → **失败** → 回到沉寂 | 量能萎缩、涨幅回吐、上涨家数回落 |
| 成功 | 沉寂 → 发现 → 成型 → 加速 | 价量持续配合、Breadth 持续扩散 |
| 见顶 | 加速 → **分歧** → 衰退 | 见下方三个警号 |

> **② 发现区是整套系统最有价值的阶段** —— 低确定性、高潜在赔率。

### 5.4 衰退的三个警号

| # | 警号 | 长什么样 |
| :-: | --- | --- |
| 1 | **量增价滞** | 成交额 ↑↑↑↑，涨幅从 +5% 掉到 +0.5% |
| 2 | **冲高回落** | 盘中最高 +6%，收盘只剩 +1% |
| 3 | **上涨家数回落** | 上涨占比 80% → 55% → 35% |

## 六、判断三层（闭环）

```
  判断·Layer 1 · 板块 Regime
  个股状态向量 → 聚合 → Flow · Breadth · Efficiency · Crowding
                              │
                              ▼
                        阶段 Stage ① ② ③ ④ ⑤
                              │
                              ▼
  判断·Layer 2 · 板块 Momentum
        这个阶段正在向哪里移动？
        发现→成型 ↑↑   成型→加速 ↑↑
        加速→加速 →    加速→衰退 ↓
                              │
                              ▼
  判断·Layer 3 · 个股选择 Stock Selection
        按阶段用不同选股逻辑（见 §7）
                              │
                              ▼
        操作：不关注 / 研究 / 参与 / 谨慎 / 退出
                              │
                              ▼
        明天同一时间，再看同一批指标
        （回到 Layer 1 —— 这就是闭环）
```

> **Layer 2 比 Layer 1 更重要。** Stage 是**状态**，Direction 是**变化**。
> （注意：这是「判断」的三层；§3.5 是「数据」的三层，两者不同。）

## 七、个股层：五个类别，核心只抓 8 个

> 系统最终不是买板块，而是：**发现板块 → 判断阶段 → 在板块内部找最优股票/ETF**。
> 个股指标**不要和板块完全一样**。

### 7.1 核心 8 个

| # | 指标 | 公式 | 回答什么 |
| :-: | --- | --- | --- |
| 1 | **5D 相对板块强度** | 个股 5 日收益 − 板块 5 日收益 | 有没有跑赢板块 |
| 2 | **20D 相对板块强度** | 同上，20 日 | 中期相对强度 |
| 3 | **成交额异常** | 今日成交额 ÷ MA20 成交额 | 有没有**异常**资金 |
| 4 | 成交额趋势 | MA5 ÷ MA20 成交额 | 是不是持续 |
| 5 | 价格推进效率 | 区间收益 ÷ 成交额放大 | 资金有没有"杀伤力" |
| 6 | 突破 / 趋势状态 | 收盘 > 20 日最高 | 价格有没有确认 |
| 7 | **收盘位置 CLV** | （收盘 − 最低）÷（最高 − 最低） | 有没有冲高回落 |
| 8 | **回撤恢复能力** | 收复幅度 ÷ 回撤幅度 | 有没有承接 |

### 7.2 三个必须注意的点

**① 成交额要看「异常程度」，不是绝对值**

| 股票 | 成交额 | 倍数 |
| --- | :-: | :-: |
| A | 5 亿 → 15 亿 | **3 倍** ← 资金行为更异常 |
| B | 50 亿 → 70 亿 | 1.4 倍 |

**② 突破要看「质量」，不是「有没有突破」**

```
突破 20 日高点 + 成交额 = MA20 × 1.8 + 收盘接近全天最高  →  漂亮的突破
突破 20 日高点 + 成交额 × 2         + 盘中 +8% 收盘 +1%  →  质量明显差
```

**③ 收盘位置 CLV 最能识别「冲高回落」**

`CLV = 0.90` → 收盘接近最高点（强）　`CLV = 0.15` → 冲高后大量回落（弱）

### 7.3 个股拥挤度惩罚

```
20 日涨幅分位 + 60 日涨幅分位 + 成交额分位 + 波动率分位
```

> 涨幅 95 分位、成交额 98 分位、波动率 97 分位
> → 这只股票**已经非常拥挤**，**即使它仍然很强，也应降低风险收益比评分**。

                    市场

                     ▼

          ┌──────────┴──────────┐
          ▼                     ▼

## 九、每日流程与参数

### 9.1 每天怎么做

| 步 | 做什么 | 在哪 |
| :-: | --- | :-: |
| 1 | 收盘后拉**一次**全市场日线 | Tushare |
| 2 | 算每只股票的**状态向量** | 本地 |
| 3 | 按板块成员聚合出 Flow / Breadth / Efficiency / Crowding | 本地 |
| 4 | 判阶段（Layer 1） | 本地 |
| 5 | 与昨天比，判移动方向（Layer 2） | 本地 |
| 6 | 只在 ②③④早期 进入个股排名（Layer 3） | 本地 |
| 7 | 板块字典/成分有变化时才更新 | 东财 |

> **第一次用**（或想回看更早的行情）先补一次历史空档，之后每天只补当天那一根：
>
> ```bash
> python3 hunter.py backfill market --days 30   # 一次性：最近 30 个交易日，一天 1 个请求
> python3 hunter.py update stock                # 一次性：个股名字字典，1 个请求
> python3 hunter.py fetch market                # 每天收盘后：补当天这一根
> ```
>
> 补历史是**可中断续跑**的：本地已有的交易日不会重复拉，Ctrl-C 之后重跑接着补。
>
> **每天那一次 `fetch market` 还有第二个作用：它是整个系统的「交易日钟」。**
> 其余所有「本地是不是最新的」都以它为准（`stock_daily` 的最大交易日），
> 于是批量刷板块/自选时，已经到那天的直接跳过、一个请求都不发 ——
> 而且**永远不需要判断「今天是哪天、今天开不开市」**（那种判断在节假日必然算错）。

**用哪一层？** 东财的行业板块其实是**申万分类**（本地只用**一级 31 + 二级 128**，
存在 `board_tree` 表里；`show board` 按一级分标签、二级排在下面）。
实测（39 个交易日、本地全市场数据）：

| 板块 | 成分股 | 日收益标准差 | 对上级的倍数 |
| --- | :-: | :-: | :-: |
| 电子（一级） | 521 | 2.74% | — |
| └ 半导体（二级） | 186 | 3.30% | **1.20×** |
| 电力设备（一级） | 412 | 1.72% | — |
| └ 电池（二级） | 107 | 1.79% | 1.04× |
| └ 锂电池（三级） | 33 | 1.97% | 比主题还小 |

> 结论：**二级确实更灵敏，但"成分股越少越灵敏"是错的** ——
> 锂电池只有 33 只却最稳（都是大市值龙头），半导体 186 只却最活。
> 决定灵敏度的是**主题内部齐不齐**，不是数量。
>
> 所以两种层级是**分工**：一级看大类资金方向（稳、慢，适合确认「钱在这个方向」），
> 二级/三级找细分主题的启动点（灵敏、噪声大，适合找「启动的那一下」）。
> 这也正好对上 §9.2 那个「先粗筛 Top30，再细看 Top10」的两段式。

**「关注池」怎么来**：人不可能盯住 500 个板块，所以工具里有个**自选** ——
看到资金脚印就加进来，势能走完就移出去（`hunter.py watch / unwatch`）。
它和 §9.2 那个「自动粗筛」是两条并行的路：
自选是你**手动**圈定的池子，粗筛是让程序**自动**从全市场里挑出候选；
两者最终都汇到同一个地方 —— 对这个池子做完整的势能分析。

### 9.2 粗筛层：先排名，再细看

板块可能很多（几百个），不必每个都做完整分析：

```
500 个板块
    ↓  用全市场个股数据聚合出板块排名
  Top 30        ← 板块 5D收益 / Flow / Breadth / Efficiency 排名
    ↓  再做详细势能分析
  Top 10
    ↓
  ETF 筛选
```

| 板块 | 5D 收益 | Flow | Breadth | Efficiency |
| --- | :-: | :-: | :-: | :-: |
| 商业航天 | 8.4% | 1.8 | 76% | 高 |
| 机器人 | 7.2% | 1.6 | 69% | 高 |
| AI | 5.8% | 1.5 | 61% | 高 |
| 医药 | 1.2% | 0.9 | 43% | 中 |
| 银行 | -0.4% | 0.8 | 31% | 低 |

### 9.3 输出格式

> **必须是一句话**：`板块 X 现在在 ③ 成型，正在向 ④ 加速移动。`
> 落到操作上：`主要参与区，但开始盯 Efficiency Trend。`

### 9.4 参数

> 用 **20 日观察窗口** 寻找 **15 日趋势中的 5 日启势**，
> 用板块势能筛选 ETF，目标持有一波约 **10 个交易日**。

| 参数 | 值 |
| --- | :-: |
| 观察窗口 | 20 日 |
| 分位窗口 | 20 / 60 日 |
| 启势窗口 | 5 日 |
| 目标持有 | ≈ 10 个交易日 |

## 十、边界与后续

### 10.1 已知边界

| 边界 | 应对 |
| --- | --- |
| 前 20 个交易日没有分位（启动期） | 先记录，不着急下结论 |
| 没有复权数据（120 积分） | 收益率用 `∏(1+pct_chg)−1`；价格绝对值类指标先容忍 |
| 板块成分会变，而成员表是**快照** | 只影响**跨年回测**（略偏乐观）；看当下势能不受影响。<br>真要回测再补历史成员表 —— 行情不用重采 |
| 个股名字不在 `stock_daily` 里 | ✅ 已解决：`stock_list`（代码→名字）单独一张字典表，`update stock` 一次请求拉全市场 |
| 涨停家数 | 板块接口不提供 → 拿到全市场日线后**自己算**；<br>**绝不逐个板块翻成分股**（那才是触发反爬的操作） |

### 10.2 后续计划

1. 个股状态向量 → 聚合板块 Breadth（**解锁 §4.2 四项**）
2. 板块的 **risk 指标**
3. **势能的类型**（不同形态的势，走法不一样）
4. 需要跨年回测时：补 `concept_member_history`（行情一行都不用重采）

### 10.3 当前构建程度

> 首先通过**个人的直观感受**训练盘面直觉，把这个模型构建到个人认知里，
> 能够根据当前板块的行情，判断它处于哪个势能阶段。

**顺序**：先攒数据 → 对照模型看盘 → 用直觉校准模型 → 最后才是自动化判断。
